# Home Poker

Приложение для управления домашними покерными сессиями на iOS: учёт игроков, банк, расходы, рейк/чаевые, таймер турнира и автоматический settlement.

**Кому полезно**
- Организаторам домашних кеш‑игр и турниров, которым нужен прозрачный учёт денег.
- Игрокам, которые хотят видеть понятные результаты и минимальное количество переводов.
- Ведущим турниров, которым нужен таймер блайндов и шаблоны структуры.

**Ключевая идея**
В приложении есть две экономики: игровые фишки и реальные деньги. Все игровые операции происходят в фишках, а расчёты между людьми — в деньгах. Конвертация контролируется коэффициентом `chipsToCashRatio`.

---

**Основные возможности**
- Создание сессий (кеш или турнир), настройка блайндов, места, формата.
- Управление игроками: buy‑in, add‑on, cash‑out, возврат в игру.
- Банк сессии: депозиты, выплаты, ответственный, контроль баланса.
- Учёт рейка и чаевых, распределение рейкбека.
- Учёт расходов, распределение долей по игрокам, оплата из банка или рейка.
- Settlement: автоматический расчёт кто кому и сколько должен, с минимизацией переводов.
- Отдельная вкладка поиска с фильтрацией по названию, месту, формату и статусу.
- Таймер турнира: шаблоны уровней, редактирование структуры, уведомления по уровням.
- Экспорт/импорт сессий в файл `.pokersession`.

**Ограничения текущей версии**
- Турнирный режим присутствует в UI и модели сессии, но settlement пока рассчитан под кеш‑логику (chip buy‑in/cash‑out). Турнирный settlement запланирован, но ещё не подключён.
- Пользовательские шаблоны таймера пока не сохраняются постоянно (TODO в `TemplateService`).

---

**Как это работает (пользовательский сценарий)**
1. Создаёте сессию и задаёте параметры (формат, блайнды, коэффициент конвертации).
2. Добавляете игроков и операции с фишками.
3. Фиксируете банковские операции, расходы, рейк и чаевые.
4. Завершаете игру и запускаете settlement.
5. Приложение выдаёт:
- выплаты из банка победителям,
- возвраты в кассу за расходы,
- прямые переводы между игроками,
- переводы в кассу (если у игрока остался долг).

---

**Экономики и расчёты**

**Chip economy**
- Игровые транзакции живут в фишках (`PlayerChipTransaction`).
- Итог игрока в фишках:
```
netChips = cashOut - buyIn
```

**Money economy**
- Конвертация в деньги:
```
netCash = netChips × chipsToCashRatio
```
- Рейкбек добавляется к `netCash` до всех дальнейших расчётов.
- Расходы изменяют `netCash`. Если игрок оплатил расход, он получает возврат. Если у игрока есть доля в расходе, она уменьшает его баланс.

---

**Settlement: актуальная логика**
Расчёт выполняется в `SettlementService` и учитывает банк, рейкбек и расходы.

**Этапы**
1. Считаем `netChips` и `netCash` по транзакциям фишек.
2. Применяем рейкбек.
3. Учитываем расходы: `netCash += expensePaid - expenseShare`.
4. Считаем `netContribution` игрока (депозит − выплаты из банка) и добавляем в `netCash`.
5. Если банк есть, распределяем фактический баланс банка победителям.
6. Формируем окончательных кредиторов/должников и строим прямые переводы P2P.
7. Дополнительно формируем возвраты в кассу за расходы, оплаченные из банка, и переводы игрока в кассу, если после P2P остался долг.

**Что возвращает settlement**
- `bankTransfers`: выплаты из банка победителям.
- `returnToBankTransfers`: возвраты в кассу по распределённым расходам.
- `playerTransfers`: прямые переводы между игроками.
- `playerToBankTransfers`: долги в кассу после P2P.

---

**Банк и расходы**

**Банк сессии (`SessionBank`)**
- Хранит все денежные движения: депозиты, выплаты, оплаты расходов и чаевых.
- `netBalance` = все депозиты − все выплаты.
- Рейк и чаевые отражаются как резервы в банке.

**Расходы (`Expense`)**
- Имеют общую сумму, плательщика и распределение долей.
- Расход может быть частично покрыт из рейка (`paidFromRake`).
- Оплата расхода из банка фиксируется транзакцией `expensePayment`.
- Расход считается полностью распределённым, когда:
```
sum(distributions) + paidFromRake == amount
```

---

**Таймер турнира**
- Отдельная вкладка с выбором шаблона и настройкой структуры.
- Есть набор встроенных шаблонов (Turbo/Standard/Deep, разные размеры).
- Поддерживаются уровни блайндов и перерывы.
- Таймер сохраняет состояние и умеет работать с локальными уведомлениями.

**Пользовательские шаблоны**
- В UI можно редактировать и сохранять как «новый шаблон».
- Постоянное хранение пока не подключено (TODO в `TemplateService`).

---

**Экспорт/импорт сессий**
- Формат: JSON внутри `.pokersession`.
- Сервис: `SessionTransferService`.
- Экспорт включает игроков, транзакции, банк и расходы.
- Импорт создаёт новую сессию с новыми UUID и корректно восстанавливает связи.
- Импортируемые сессии сейчас создаются как `.cash`.

**Архитектура**

**Стек**
- Swift 5.9+
- SwiftUI
- SwiftData
- MVVM + Service Layer + Repository

**Слои**
- View: SwiftUI экраны и компоненты.
- ViewModel: управление состоянием и валидацией.
- Services: бизнес‑логика (Session/Settlement/Timer/Transfer).
- Repository: доступ к данным (SwiftData).
- Data: модели SwiftData + DTO.

**Модель данных (SwiftData)**

**Сущности**
- `Session`
- `Player`
- `PlayerChipTransaction`
- `SessionBank`
- `SessionBankTransaction`
- `Expense`
- `ExpenseDistribution`
- `SettlementTransfer`

**Ключевые связи и правила удаления**
- `Session → Players` (cascade)
- `Session → Expenses` (cascade)
- `Session → SessionBank` (cascade)
- `Session → SettlementTransfer` (cascade)
- `Player → PlayerChipTransaction` (cascade)
- `SessionBank → SessionBankTransaction` (cascade)
- `Expense → ExpenseDistribution` (cascade)
- `Expense.payer` и `ExpenseDistribution.player` (nullify)

---

**Навигация (основные экраны)**
- Сессии: список, детали сессии, банк, расходы, settlements.
- Поиск: фильтрация по сессиям.
- Таймер: выбор/редактирование шаблонов и активный таймер.
